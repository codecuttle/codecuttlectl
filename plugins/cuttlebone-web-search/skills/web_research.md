# Web Research Workflow

When you need information beyond your training data, follow this workflow:

## When to search
- User asks about current events, recent releases, or "latest" anything
- You need API documentation for a specific library version
- You're unsure about a library name, function signature, or configuration option
- The user references something you don't have confident knowledge about
- Error messages that might have known solutions or bug reports

## Search tips
- Use specific, targeted queries rather than broad ones
- Include version numbers when searching for library docs (e.g., "go 1.25 generics")
- For error messages, quote the unique part of the error
- Use the current year when searching for recent information
- If the first search doesn't help, reformulate with different terms

## When to fetch
- You found a relevant URL in search results and need the full content
- User shared a URL they want you to read
- You need to read documentation at a specific page
- GitHub READMEs, issue threads, or code files

## Best practices
- Search first, then fetch specific URLs from the results if you need more detail
- Don't fetch URLs blindly — use search to find the right page first
- Summarize findings for the user rather than dumping raw content
- If a search returns no useful results, try alternative queries before giving up
